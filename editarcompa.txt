SISTEMA DE EDICIÓN DE COMPAÑEROS
================================

Se ha implementado una nueva funcionalidad para editar los compañeros cargados en el sistema.

CARACTERÍSTICAS:
----------------
1. Botón "Editar" en la cuadrícula de compañeros (solo visible para administradores).
2. Formulario pre-cargado con los datos actuales del compañero.
3. Posibilidad de actualizar metadatos (Nombre, Animación, Partículas) sin necesidad de volver a subir archivos.
4. Si se suben nuevos archivos durante la edición, estos reemplazarán las URLs anteriores en la base de datos.
5. Nuevas opciones de configuración:
   - Animación: "Flotante (Sin Rotación)" (float-static).
   - Partículas: "Sin Partículas" (none).

CONFIGURACIÓN EN SUPABASE (SQL):
--------------------------------
Si la edición no funciona, asegúrate de haber ejecutado este SQL en tu editor de Supabase:

```sql
-- 1. Crear tabla si no existe (con columnas de edición)
CREATE TABLE IF NOT EXISTS spirits (
    id BIGSERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    gltf_url TEXT NOT NULL,
    texture_url TEXT,
    animation_type TEXT DEFAULT 'orbit',
    particle_asset TEXT DEFAULT 'cerezo.png',
    particle_movement_type TEXT DEFAULT 'falling',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Habilitar RLS
ALTER TABLE spirits ENABLE ROW LEVEL SECURITY;

-- 3. Política de edición para administradores
DROP POLICY IF EXISTS "Admins can manage spirits" ON spirits;
CREATE POLICY "Admins can manage spirits"
ON spirits FOR ALL
TO public
USING (
  EXISTS (
    SELECT 1 FROM usuarios
    WHERE role = 'admin'
  )
);

-- 4. Asegurar columna en tabla usuarios
DO $$
BEGIN
    IF NOT EXISTS (SELECT 1 FROM information_schema.columns WHERE table_name='usuarios' AND column_name='selected_spirit_id') THEN
        ALTER TABLE usuarios ADD COLUMN selected_spirit_id BIGINT REFERENCES spirits(id);
    END IF;
END $$;
```

NOTA SOBRE ALMACENAMIENTO:
--------------------------
Cuando se edita un compañero y se suben nuevos archivos, estos se guardan en una nueva carpeta dentro del bucket `spirits`. Los archivos antiguos permanecen en el almacenamiento a menos que se elimine el compañero por completo usando el botón "Eliminar" (que limpia todos los archivos asociados).

ACTUALIZACIÓN DE ESCALA (SQL):
-----------------------------
Para habilitar la modificación del tamaño de los modelos, ejecuta este SQL:

```sql
ALTER TABLE spirits ADD COLUMN IF NOT EXISTS scale FLOAT DEFAULT 1.8;
```
