Explicación técnica sobre el escaneo 100% automático (Ajuste Cero):

Estado Actual del Proyecto:
Se ha implementado una arquitectura de "Escaneo por Franjas de Interés" (ROI) con las siguientes mejoras de robustez:
1. ROIs Fijas y Expandidas: En lugar de depender de una imagen PNG que puede fallar al cargar, el sistema ahora tiene grabadas las coordenadas proporcionales exactas (10% superior e inferior). Se han ampliado un 15% para permitir que la carta se detecte aunque no esté perfectamente centrada.
2. Pipeline de Multi-Pasada: Para cada captura, el sistema procesa la imagen 3 veces con diferentes niveles de brillo y contraste (Normal, Oscuro, Claro). Esto soluciona los problemas de reflejos o falta de luz automáticamente.
3. Validación de Patrones (Regex): El sistema es "silencioso". Solo muestra resultados cuando detecta un código que cumple con el formato real de una carta (8 dígitos para YGO, fracciones o promos para Pokémon). Esto elimina el "ruido" visual de letras aleatorias.
4. Pre-procesado Avanzado: Se aplica un reescalado 4x y un filtro de contraste ultra-agresivo para que el OCR lea texto incluso si la imagen original es borrosa.

Por qué no se puede lograr el "Cero Ajuste" Total (detectar la carta rotada o en cualquier ángulo):
Para lograr eso, se necesitaría Visión Computacional pesada:
- Detección de Rectángulos por IA: Requeriría TensorFlow.js o OpenCV.js para encontrar los 4 puntos de la carta en el aire y "enderezarla".
- Rendimiento: Ejecutar estos modelos en móviles antiguos causaría lag extremo y sobrecalentamiento.
- Restricción de Código: Integrar estas librerías requiere cambios profundos en la estructura del proyecto que violarían la orden de "no tocar otras partes del código".

Conclusión:
La implementación actual es la más robusta posible dentro de un navegador web sin usar IA pesada. Es rápida, automática y perdona errores de alineación.
