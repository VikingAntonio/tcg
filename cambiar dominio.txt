================================================================================
GUÍA COMPLETA Y LISTA DE MODIFICACIONES PARA CAMBIO DE DOMINIO
(Migración de vikingtcg.xyz a un NUEVO DOMINIO a futuro)
================================================================================

Este documento detalla todas las acciones, cambios en archivos, configuraciones
en Supabase, pasarelas de pago y proveedores que deberán realizarse en caso de
adquirir y utilizar un nuevo dominio en lugar de vikingtcg.xyz.

--------------------------------------------------------------------------------
1. CONFIGURACIÓN EN SUPABASE DASHBOARD
--------------------------------------------------------------------------------
* Authentication -> URL Configuration:
  - Cambiar "Site URL": Modificar https://vikingtcg.xyz por https://tunuevodominio.com
  - Cambiar "Redirect URLs":
    * Agregar https://tunuevodominio.com/**
    * Agregar https://tunuevodominio.com/reset-password.html
    * Agregar https://tunuevodominio.com/admin.html
    * Agregar https://tunuevodominio.com/session-bridge.html
    * Agregar https://tunuevodominio.com/widgets.html
    (Nota: Si mantienes activo el dominio anterior durante la transición, deja ambos
    en las Redirect URLs permitidas para no romper sesiones viejas).

* Authentication -> Email Templates:
  - Verificar en plantillas de Confirm Signup, Magic Link y Reset Password si hay
    enlaces absolutos o nombres que mencionen vikingtcg.xyz.

* Base de Datos Supabase (Tablas con datos registrados):
  - Tabla `widget_domains`:
    Si los clientes o tú mismo tenían autorizado el dominio vikingtcg.xyz para
    embebidos de widgets, registrar o actualizar al nuevo dominio.
  - Tabla `usuarios`:
    * Verificar columnas `store_logo` o `banner_url` si algún usuario tiene guardada
      la imagen por defecto 'https://vikingtcg.xyz/favi.png'. De ser necesario,
      ejecutar script SQL:
      UPDATE usuarios SET store_logo = REPLACE(store_logo, 'vikingtcg.xyz', 'tunuevodominio.com') WHERE store_logo LIKE '%vikingtcg.xyz%';
  - Tabla `preorders` y `sealed_products`:
    * Verificar si en descripciones o imágenes hay enlaces absolutos a vikingtcg.xyz.
  - Supabase Auth Users (`auth.users`):
    * OJO con usuarios creados por nombre de usuario ficticio:
      En `docs/js/binders.js` se hace login con `${user}@vikingtcg.xyz`.
      Si se cambia ese sufijo a `@tunuevodominio.com`, los usuarios ya registrados
      en auth.users con `@vikingtcg.xyz` requerirán una migración en `auth.users`
      o mantener la compatibilidad en el código para permitir login con ambos dominios.

8. LINKS PÚBLICOS, QR CODES Y REDES SOCIALES
--------------------------------------------------------------------------------
* Links Públicos de Tiendas y Binders:
  - En el código actual, la mayoría de los módulos generan los links públicos de forma
    dinámica utilizando `window.location.origin` (por ejemplo:
    `const publicUrl = `${window.location.origin}/${identifier}`;` en admin.js y landing.js).
    Esto significa que AUTOMÁTICAMENTE adoptarán el nuevo dominio en cuanto los usuarios
    entren desde tunuevodominio.com.
  - Sin embargo, los links que los clientes ya hayan compartido físicamente o en redes
    (en biografías de Instagram, WhatsApp, tarjetas de presentación impresas con QR):
    * Seguirán apuntando a vikingtcg.xyz/su_tienda.
    * ACCIÓN REQUERIDA: Es fundamental mantener el dominio viejo vikingtcg.xyz activo
      con una redirección 301 (permanente) a nivel DNS o Cloudflare hacia tunuevodominio.com/$1
      para que ningún cliente pierda ventas ni escaneos de códigos QR previos.

* Enrutador SPA 404 (`docs/404.html`):
  - El script ya utiliza `l.hostname` dinámico para redirigir paths cortos
    (ej: tunuevodominio.com/mitienda -> tunuevodominio.com/public.html?id=mitienda).
    Funcionará de manera transparente en el nuevo dominio.

--------------------------------------------------------------------------------
9. PASARELA DE PAGOS (STRIPE)
--------------------------------------------------------------------------------
* Dashboard de Stripe (Desarrollo y Producción):
  - Webhooks:
    El webhook de Stripe apunta a la Edge Function de Supabase
    (https://<project-ref>.supabase.co/functions/v1/stripe-webhook), por lo que
    las notificaciones servidor-servidor NO se rompen por el cambio de dominio.
  - Configuración de Portal de Clientes y Checkout:
    Actualizar en Stripe -> Settings -> Customer Portal y Branding el dominio
    autorizado y enlaces a términos / privacidad / soporte a tunuevodominio.com.

--------------------------------------------------------------------------------
10. RESUMEN DE PASOS EN ORDEN CRONOLÓGICO PARA EL DÍA DE LA MIGRACIÓN
--------------------------------------------------------------------------------
1. Comprar y configurar DNS del nuevo dominio apuntando a GitHub Pages.
2. Modificar `docs/CNAME` con el nuevo dominio.
3. Actualizar Site URL y Redirect URLs en Supabase Auth.
4. Actualizar `supabase/functions/create-checkout-session/index.ts` con el nuevo dominio y desplegar la Edge Function.
5. Reemplazar 'vikingtcg.xyz' por 'tunuevodominio.com' en:
   - `docs/js/viking-widget.js`
   - `docs/widgets.html`
   - `docs/js/landing.js` y `docs/js/landing2.js`
   - `docs/admin.html`
   - `docs/session-bridge.html` y `docs/js/vikingdevUI.js`
   - Los tags `<link rel="icon">` en todos los archivos HTML (o pasarlos a './favi.png').
6. Incrementar la versión del Service Worker en `docs/sw.js`.
7. En el registrador del dominio anterior (vikingtcg.xyz), configurar redirección 301
   hacia el nuevo dominio para preservar tráfico y códigos QR existentes.
