========================================================================
                      CONFIGURACIÓN DEL SISTEMA DE ATAQUE
========================================================================

El sistema de ataque visual implementado en duel.html utiliza un lienzo SVG
dinámico (#attack-arrows-overlay) que dibuja vectores fluorescentes (con filtros de
neón, gradientes animados, insignias interactivas y etiquetas de texto descriptivas)
conectando el origen del ataque con el objetivo.

------------------------------------------------------------------------
¿CÓMO FUNCIONA EL SISTEMA DE ATAQUE?
------------------------------------------------------------------------
1. MODO DE SELECCIÓN (Atacar):
   - Al hacer clic en "Atacar" en el menú rápido o en el menú contextual de una carta
     en campo, se activa la función global: window.startAttackTargetingMode(attackerCard).
   - Esta función pone al tablero en un estado de selección (.selecting-zone) y abre
     un panel informativo superior indicando al jugador que seleccione un objetivo.
   - Las demás cartas del oponente que estén en el campo se vuelven "clicables".
   - Al hacer clic en la carta objetivo, se crea una relación de ataque en state.attacks
     { attackerId, targetId, isDirect: false } y se dibuja el vector en el canvas.

2. ATAQUE DIRECTO:
   - Al presionar "Atk Directo", se llama inmediatamente a window.performDirectAttack(attackerCard).
   - Genera una relación { attackerId, targetId: null, isDirect: true } apuntando
     simétricamente a la zona del jugador rival (superior o inferior).

3. REDIBUJADO CONSTANTE:
   - Toda acción del juego (mover cartas, refrescar pantalla, sincronizar con el oponente,
     robar cartas, etc.) vuelve a calcular y re-renderizar las flechas mediante
     window.drawAttackArrows().

------------------------------------------------------------------------
¿QUÉ SE NECESITA PARA QUE FUNCIONE EN TU ENTORNO? (REQUISITOS CLAVE)
------------------------------------------------------------------------
Si actualmente no ves las flechas o al dar clic no pasa nada, se debe principalmente
a tres posibles factores de configuración en tu entorno:

1. CANAL DE SUPABASE (Realtime Broadcast):
   El código utiliza `commChannel.send(...)` para sincronizar los estados de ataque
   entre los dos jugadores a través del canal Supabase "room:<room_id>".
   - SI ESTÁS EN MODO PRÁCTICA INDIVIDUAL:
     En ocasiones, las llamadas de red broadcast pueden fallar de forma silenciosa si
     el canal de Supabase no se ha terminado de inicializar correctamente o si la
     autenticación/sesión expira.
   - SOLUCIÓN IMPLEMENTADA:
     He optimizado el código de dibujo para que se renderice localmente DE INMEDIATO,
     incluso si la conexión o el canal Realtime de Supabase está offline o retorna errores.

2. CARTAS LOGICAMENTE EN CAMPO:
   El algoritmo de renderizado de las flechas de ataque contiene un filtro de seguridad
   riguroso para prevenir "flechas huérfanas" o fantasmas:
   - Las cartas deben estar ubicadas en zonas activas del campo (como "monster_1_x",
     "monster_2_x", "spell_1_x", "spell_2_x", etc.).
   - Si las cartas no están correctamente asignadas en estas zonas, o si se mueven a
     la mano/cementerio, la flecha se limpia automáticamente. Asegúrate de probarlo
     con cartas colocadas en zonas del tablero.

3. EVITAR INTERCEPCIÓN DE EVENTOS (pointer-events):
   - El canvas SVG (#attack-arrows-overlay) tiene asignado la propiedad CSS
     `pointer-events: none` para garantizar que no obstruya los clics sobre las cartas.
   - Si por algún motivo tienes otra capa superpuesta o si el menú rápido de la carta
     no está propagando el evento click correctamente, el disparador no se ejecuta.
   - SOLUCIÓN IMPLEMENTADA:
     Aseguramos que el botón del menú de cartas (.btn-field-attack y .btn-field-direct)
     y el menú contextual utilicen `e.preventDefault()` y `e.stopPropagation()` para
     ejecutar limpiamente el modo de selección sin interferencias del arrastre.

------------------------------------------------------------------------
MEJORAS REALIZADAS EN ESTA VERSIÓN:
------------------------------------------------------------------------
- Garantizamos renderizado local síncrono al instante de declarar el ataque,
  previniendo cualquier dependencia de latencia con la base de datos de Supabase.
- Agregamos logs claros directamente a la consola web (F12) cada vez que se declara
  un ataque para que puedas monitorear en tiempo real qué cartas están interactuando.
- Sincronizamos las insignias de ataque en la parte superior derecha de las cartas
  (p. ej., "⚔️ ATACANDO" en rojo/cian neón y "💥 ATK DIRECTO") para dar una referencia
  visual ineludible incluso si el oponente desplaza sus cartas.
